```toml
[dependencies]
amethystate = { version = "0.20", features = ["redb"] }
```

Движка по умолчанию нет. Приложение само называет тот, что будет держать его
файл, а крейт, который только объявляет структуры или служит адаптером к
фреймворку, не называет никакого и оставляет выбор приложению. Всё ниже — про
то, какой назвать.

## Выбор движка

Хранилище могут держать пять движков, и ровно один из них открывает файл. Фичи
Cargo решают, какие из пяти вообще войдут в сборку; какой возьмётся за файл —
говорят при открытии, через `StoreBuilder::backend`. Если не сказать, берётся
первый включённый.

| feature | движок | файл |
| --- | --- | --- |
| `redb` | redb | `.redb` |
| `sqlite` | SQLite | `.db` |
| `json` | JSON | `.json` |
| `toml` | TOML | `.toml` |
| `ron` | RON | `.ron` |

**Текстовые движки пишут два файла**: данные и файл-спутник `.meta`. В спутнике
лежит то, без чего store не прочитает данные обратно: какая версия каждой
структуры их записала, как выглядели её поля и что уже сделал проход миграции.
Файл данных человек по-прежнему прочитает и сам по себе, но открытый без
спутника он теряет схему, под которой записан. Поэтому файлы принадлежат друг
другу, и резервная копия берёт оба. redb и SQLite держат ту же запись внутри
своего единственного файла.

Формат задаёт, что store может выразить. В
[Выборе движка](/amethystate/ru/choosing/absent-or-null/) измерено, что
каждый движок делает с одними и теми же значениями.

Сборка без движка всё равно компилируется, но store в ней не откроется:
`StoreBuilder::build` ответит `OpenStore::WouldNotOpen` и назовёт фичи, которые
надо включить.

### Несколько движков сразу

Фичи Cargo аддитивны. Если в сборке несколько движков, store, которому движок
не назвали, берёт тот, что раньше в списке **redb, SQLite, JSON, TOML, RON**.
Так что стоит какой-нибудь зависимости включить `redb`, и за такой store
возьмётся redb, что бы ни просил ваш крейт.

Скомпилировать сразу несколько - законно: инструмент, который читает тот файл,
на который его направили, или набор тестов, прогоняющий один и тот же случай
по каждому. Назовите движок явно при создании store, и этот порядок перестаёт
что-либо значить.

### SQLite

SQLite собирается из исходников, поэтому нужен C-тулчейн. Зато минимальную
версию SQLite выбирает библиотека, а не дистрибутив пользователя.

Разница не косметическая. Стоит начать пользоваться какой-нибудь возможностью
SQLite — скажем, `STRICT`-таблицами, — и минимум прыгает до 3.37. В самом файле
это никак не отмечено, поэтому SQLite постарее скажет не «версия не та», а
«схема испорчена» — про целый и невредимый файл.

```toml
amethystate = { version = "0.20", features = ["sqlite"] }
```

## Tauri

Интеграция с Tauri включает плагин, асинхронный бэкенд и генератор биндингов
для Rust и TypeScript. Включается через feature `tauri`, рядом с движком:

```toml
amethystate = { version = "0.20", features = ["tauri", "redb"] }
```

Настройка и использование:
[Интеграция с Tauri](/amethystate/ru/integrations/tauri/).
