## Для чего нужны миграции

Структуры состояния развиваются. Поля переименовывают, типы меняются, добавляются новые поля. Без слоя миграций любое изменение структуры либо молча производит неверные данные, либо заставляет вас разбираться с версионированием руками.

`amethystate` явно отслеживает версии схемы и выполняет нужные шаги преобразования при запуске, до того как заработает какой-либо код приложения.

## Что мигрирует, а что нет

Мигратор работает исключительно с сохраняемыми данными.

| Вид поля | Мигрирует? |
|------------|-----------|
| Обычные поля | ✓ |
| Структуры `nested` | ✓ |
| Поля `volatile` | ✗ — только в памяти, сохранённых данных нет |

## Как работает версионирование

У каждой структуры `#[amethystate]` есть атрибут `version`, по умолчанию `0`:

```rust
#[amethystate(prefix = "app", version = 2)]
pub struct AppConfig { ... }
```

При запуске `amethystate` читает версию, сохранённую в базе для каждого префикса, и сравнивает её с версией в коде. Если они различаются, мигратор ищет зарегистрированный шаг миграции, который перекрывает этот разрыв, и выполняет его.

Если для разрыва не зарегистрирован ни один шаг, запуск падает. Если версия в базе выше версии в коде, запуск блокируется, чтобы не испортить данные.

## Автоматический сбор

Самая простая настройка автоматически собирает все шаги миграции, объявленные через `#[migrate]`:

```rust
let store = StoreBuilder::new("./app.redb")
.collect_migrations()
.build()?;
```

Больше ничего настраивать не нужно, если все ваши шаги объявлены макросом.

Для случаев, где кодогенерации не хватает — логика между узлами, дозаполнение данных, внешние источники данных, — см. [Ручные миграции](./manual).

## Что происходит при чистой установке

На первом запуске сохранённой версии нет — база пуста. `amethystate` инициализирует все поля их значениями из `#[amestate(default = ...)]` и записывает текущую версию. Ни один шаг миграции не выполняется.

## Дрейф схемы

Если вы поменяете тип поля, переименуете его или добавите либо удалите поля, не подняв версию, ни одна миграция не выполнится — но `amethystate` всё равно это заметит. На каждом запуске сохранённый хеш схемы сравнивается с текущим кодом, и любое расхождение пишется в лог как предупреждение:

```
⚠️  Schema drift detected in prefix 'app'
  + field 'timeout': Duration
  - field 'host' (exists in DB, missing in code)
  ~ field 'port': u16 -> u32
  Suggestion: increment version and write a migration if these changes are intentional.
```

| Символ | Значение |
|--------|---------|
| `+` | поле есть в коде, но отсутствует в базе |
| `-` | поле есть в базе, но убрано из кода |
| `~` | поле есть и там и там, но у него изменился тип |

Дрейф не блокирует запуск — это предупреждение, а не ошибка. Если изменения намеренные, поднимите версию и напишите шаг миграции. Если нет, возможно, вы случайно переименовали или выбросили поле.

Полный дифф доступен программно через `MigrationReport`:

```rust
let (store, report) = StoreBuilder::new("./app.redb")
    .collect_migrations()
    .build()?;

if report.has_drift() {
    for component in &report.components {
        // component.nagging contains the per-prefix diff
    }
}
```
