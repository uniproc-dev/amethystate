## Просто serde и файл

Если сейчас у вас структура, `serde` и ручной вызов загрузки и сохранения, переход прямой. Возьмите `as_root` с подходящим бэкендом, чтобы прочитать существующий файл без всякого преобразования данных:

```rust
#[amethystate(mode = "persistent", as_root)]
pub struct AppConfig {
    pub name: String,
    pub port: u16,
}
```

```toml
amethystate = { version = "0.20", default-features = false, features = ["toml"] }
```

`as_root` пишет поля прямо в корень хранилища, без пространства имён префикса, — та же плоская раскладка, что и у вашего файла. На первой загрузке `amethystate` читает существующие ключи как есть.

## Встраиваемая база (redb, sled и подобные)

Путь в `amethystate` — это список уровней, а точки в нём вы видите только там, где путь показывают: `prefix.field` для обычного поля, `prefix.field.key` для записи карты. Байты в базе выглядят иначе. Плоский движок кладёт уровни подряд, каждый заканчивая нулевым байтом, а сами нули и единицы внутри имени заменяет парами — чтобы порядок байтов совпал с порядком уровней и поддерево оказалось префиксом ключа, без всякой доборки. Точку при этом никто не экранирует: она обычный символ имени, а границу держит терминатор.

Так что сопоставлять свои ключи со строкой `prefix.field` бесполезно — совпадать надо со списком уровней. Автоматического пути из чужой раскладки нет: перед переходом нужен разовый экспорт.

Самый простой подход - написать разовый шаг миграции через API ручных миграций: читать из старой базы внутри замыкания шага и писать значения через `ctx.set`. Полное API контекста: [Ручные миграции](./manual).

## Свой формат файла

Если ваш формат не TOML, не JSON и не RON, перед первым запуском нужно разовое преобразование. Прочитайте старый файл тем парсером, которым пользуетесь сейчас, и запишите значения прямо в хранилище `amethystate`. После этого удалите старый файл и дальше отдайте сохранение `amethystate`.
