---
title: windows-reactor
---

`amethystate-reactor` читает реактивное состояние в компоненты
[windows-reactor](https://github.com/microsoft/windows-rs). Хук возвращает обычное значение —
`u16`, `String`, `Vec<(K, V)>`, — а компонент перерисовывается, когда меняется хранилище.
Подписки, переходы между потоками и очистка в вашем коде не появляются.

Reactor отрисовывает на одном потоке интерфейса, а amethystate доставляет изменения с того
потока, который их записал, - включая наблюдателя за файлом, для правок, сделанных вне процесса.
Адаптер пересекает эту границу собственным `UiMarshaller` хоста, тем же, которым пользуется
`use_async_state`.

**Реактивный режим** обязателен.

## Установка

```toml
[dependencies]
amethystate-reactor = { git = "https://github.com/uniproc-dev/amethystate" }
windows-reactor = "0.0.0"

[patch.crates-io]
windows-reactor = { path = "../windows-rs/crates/libs/reactor" }
```

`windows-reactor` на crates.io - это заглушка, пустой крейт, который держит имя, поэтому
направьте его на локальную копию `windows-rs`. Патч должен лежать в корне вашего собственного
рабочего пространства, потому что патчи не наследуются от зависимостей.

Ни один из крейтов не опубликован, пока не выпущен сам reactor, поэтому этот адаптер -
движущаяся мишень.

## Загрузка состояния

```rust
use amethystate_reactor::AmeCx;

fn app(cx: &mut RenderCx) -> Element {
    let state: NetworkState = cx.use_ame_state();
    ...
}
```

`use_ame_state` читает глобальное хранилище, поэтому ничего не нужно протаскивать через дерево
компонентов - провайдера здесь нет. Вызовите `init_global` один раз при запуске. Чтобы
использовать хранилище, которое вы держите сами:

```rust
let state: NetworkState = cx.use_ame_state_in(&store);
```

В обоих случаях срез загружается один раз на компонент, а не один раз на отрисовку. Срез,
который не загружается, вызывает панику: схема, расходящаяся с тем, что лежит на диске, - это
неисправность запуска, а не то, из чего может выпутаться отрисовка.

## Чтение

```rust
let port  = cx.use_ame(&state.port());
let theme = cx.use_ame(&state.theme());
```

`use_ame` принимает что угодно, что реализует `Observe`: `Field`, `ReactiveCell` или
`ReactiveMap`. Значение читается из хранилища один раз, при монтировании компонента;
последующие отрисовки не читают ничего. Подписка дропается, когда компонент размонтируется.

## Запись

Никакого сеттера распаковывать не надо. Компонент уже держит хендл, поэтому пишите через него:

```rust
let bump = state.port();

button("+1").on_click(move || {
    let _ = bump.set(port + 1);
});
```

Запись возвращается как обычное изменение, и следующая отрисовка её видит.

## Карты

`ReactiveMap` читается как `Vec<(K, V)>`, отсортированный по ключу:

```rust
for (name, width) in cx.use_ame(&state.widths()) {
    ...
}
```

Для одного ключа есть `use_ame_entry` — отсутствующий ключ читается как `None`:

```rust
let cpu = cx.use_ame_entry(&state.widths(), "cpu".to_string());
```

Он переподписывается, когда ключ меняется. Предпочитайте его чтению всей карты, когда вам важна
одна запись: `use_ame` на карте перечитывает каждое значение всякий раз, когда меняется любое из
них.

## Источники, которые меняются между отрисовками

`use_ame` привязывается к тому источнику, который ему дали на первой отрисовке. Когда сам
источник от чего-то зависит — выбранный элемент, маршрут, — берите `use_ame_keyed` и передавайте
то, от чего он зависит:

```rust
let value = cx.use_ame_keyed(&source, selected_id);
```

Новое значение приходит на отрисовке *после* того, как зависимости изменились, поэтому одна
отрисовка ещё показывает прежний источник. Это то же правило, которому следует React, и поэтому
`use_ame_entry` принимает ключ, а не даёт вам пересобирать источник самостоятельно.

## Что пересекает границу потоков

Изменение доставляется на том потоке, который его записал. Адаптер маршалит его на поток
интерфейса, пишет в слот хука и запрашивает перерисовку - поэтому код ваших колбэков никогда не
выполняется на чужом потоке и ничему из написанного вами не нужно быть `Send`. Значение, которое
на самом деле не изменилось, в этот момент отбрасывается и не стоит ни одной отрисовки.

По этой же причине здесь никто не просит вас крутить собственный цикл: маршаллер уже доставляет
на поток интерфейса, а отрисовку планирует фреймворк.
